# 离线持久化与聚合同步实施记录

更新日期：2026-09-06。设计依据：[整体方案](offline-storage-and-leaderboard-optimization-v1.md)。

## 已接通的路径

此前分支已经实现 SQLite 本地统计、来源枚举/断点重建、按账号隔离的同步任务、注册用户四周期计分、事务 Outbox、Redis 全量排名与前 2000 热榜，以及同一快照下的列表/本人名次/总人数。本轮在该分支上继续补齐以下路径，未触碰另一工作区的未提交修改。

1. SQLite schema v3 将事件、聚合和采集进度放入同一事务。内存计价副本仅在事务成功后替换，失败不会污染后续去重和费用。
2. 后台每轮维护按 UTC 今天及前 6 天保留事件明细；每批最多删除 2000 条，同时清理旧投递记录。即使未登录、断网、暂停采集或未收到 ACK，也不延长明细保留。老记录解析后进入持久聚合，短暂落入当前事务的明细由维护批次清除。
3. 日聚合按账号目标隔离，包含 Agent/模型 Token、代码生成及接受行数、消息数、会话/轮次时长和 Skill 指标。会话总时长优先，否则使用轮次时长；乱序或重复的会话结束不重复累计。
4. 逐请求计价信息到期折叠为日费用覆盖。清理后费用和 Token 仍可离线查询，旧事件重扫不会重复计数。
5. 桌面自动同步改发按设备/UTC 日的绝对聚合快照。重建进行中暂停发布；拒收的日期延迟重试，其他日期可以继续。快照版本、日期和摘要全部匹配后才确认，旧 ACK 不能清掉新修改。
6. 服务端保存设备日快照并标记 dirty day。Worker 对被快照覆盖的设备/日期排除旧事件计分，再叠加各设备快照，接入既有窗口分数与 Outbox 流程。重放、降分修正和重复重算均不叠加旧值。
7. 账号、设备、时间范围及全部用量删除流程纳入新快照表。修复 MySQL 8.0.34 下设备删除重算的日期类型问题。
8. 排行榜完整列表修复 TypeScript 空值检查，账号或周期变化时丢弃旧快照，避免显示上一账号的本人行。

## 聚合协议 v1

路由：`POST /v1/telemetry/aggregates`。使用现有设备 Ed25519 签名、时间窗、随机 nonce 与请求体 SHA-256 校验；不使用浏览器 Cookie 代替设备签名。

```json
{
  "schemaVersion": 1,
  "day": "2026-09-06",
  "revision": 3,
  "rows": [{
    "kind": "agent",
    "agentId": "codex",
    "providerId": "",
    "modelId": "",
    "skillKey": "",
    "skillName": "",
    "metrics": {"exact_token_total": "1000", "estimated_cost_usd_units": "120000000"}
  }]
}
```

计数使用十进制无符号整数字符串，费用单位为 10^-8 USD；请求必须是完整日快照，当前限制最多 2000 个维度行、桌面请求体最多 2 MiB，暂不支持分块提交。服务端限制维度、字段、日期和数字范围。

ACK 为 `{"day":"2026-09-06","revision":3,"sha256":"<完整请求 JSON 的 SHA-256>"}`。同版本同摘要幂等确认；同版本异摘要及旧版本拒收。首次覆盖旧事件前校验已上传的可信 Token 总量，覆盖不完整则保留旧计分并拒收，不能把部分重建当完整历史。之后允许更高版本减少数值、删除维度。

生产更新顺序：先执行 `0007_device_aggregates.sql` 并更新 API/Worker，再发布桌面。旧服务端不支持新接口时，本地继续持久采集，待传聚合保留；不能用旧事件协议回退并重新累计已被快照覆盖的范围。既有 CLI/其他宿主的事件上传通道保留。

## 验证

- 桌面无 GUI 库测试覆盖离线 90 天、105 天历史归属、七天边界、带时区时间戳、重启和重放、事务失败、费用折叠、旧 ACK、延迟重试、活动指标。
- 服务端在独立 MySQL 8.0.34 临时数据库验证真实签名请求、版本冲突、覆盖保护、聚合替换、设备/账号删除、迁移。未连接生产数据库。
- Web TypeScript 检查及排行榜相关测试。

## 尚未达到整体方案的验收项

以下是具体实现边界，不能据此宣称方案全部完成或磁盘占用恒定：

- 用户已将目标收敛为本机逐事件去重仅保留近 7 天，不再要求永久指纹压缩；启用过期删除前仍需完成历史重扫的覆盖替换，避免重复累加。当前代码未启用指纹过期。
- 当前使用每事件 SHA-256 指纹，以及按日的会话/轮次哈希和计数状态保证清理后重放、乱序和修正的幂等。这些不含事件负载/聊天正文，但仍随事件或会话数量增长。设计中来源覆盖水位与分段替换的进一步压缩尚未实现；此实现不满足“仅来源级元数据”的最终容量目标。
- 超期费用保留最终日覆盖，已折叠的未知计价明细不能仅凭普通日总量精确重新定价。晚到费用替换和旧解析口径修正仍需完善来源级重建与计价充分统计，不能承诺所有历史都可重新估算。
- 首次覆盖保护检查可信 Token，不是对所有旧 Skill、代码、费用维度的完整覆盖证明。来源丢失时不应强制跳过拒收或直接清空旧云端数据。
- 旧备份恢复的版本协商、超大日快照分块、来源内容改写后的完整覆盖替换，仍需后续实现及故障测试。
- 明细删除后的空页供 SQLite 复用，文件不保证马上变小；增量空间回收、异常重启时钟校验、超大历史容量和 24 小时空闲增长仍需验收。
- 尚未完成十万用户 Redis 读写压测、所有故障注入、生产灰度和安装包发布。本次提交不更改线上服务或用户已安装客户端。
