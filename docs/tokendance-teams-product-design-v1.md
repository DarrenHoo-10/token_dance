# TokenDance 团队功能与 UI 交互设计 v1

日期：2026-09-06。状态：设计提案；**2026-09-12 修订成员关系 / 自动共享 / 退出留量**（锁定结论，不再按「只加入不共享」或「退出删除团队用量」实现）。原型仍使用演示数据。

本次更新：邀请成员支持直接分享链接，与邮箱邀请并列进入首版。2026-09-12 起：在队即自动计入全部用量维度；加入只从 `joined_at` 起算；退出后用量留在匿名「历史用户」桶；不保存已结束的成员关系台账。

技术落地见 [团队模块技术方案 v1](tokendance-teams-technical-design-v1.md) 与 [团队分析静态物化技术方案](tokendance-teams-static-metrics-v1.md)。

## 1. 定位与首版决策

让一组使用 AI 编程工具的人，在加入团队后自动汇总用量，了解团队投入、工具构成和活跃情况。

核心闭环：**创建团队 → 邀请同伴 → 确认加入（即自动计入全部用量维度） → Collector 自动同步 → 查看团队趋势和成员贡献**。

目标用户优先为小型研发团队、工作室和学习小组。Token 数量衡量使用量，不代表代码质量、生产效率或绩效；界面使用「用量 / 贡献」，不使用「效率冠军 / 员工评分」。

建议首版决策：

- **确定规则：每个账号同时最多属于一个团队，所有者、管理员、成员均适用；创建团队也占用这唯一的名额。** 不提供多团队或团队切换功能。
- 团队默认为私有，仅成员可访问；公开团队主页和跨团队排行放到下一期。
- 使用所有者、管理员、成员三级固定权限，不设计自定义角色。
- 公开资料 / 头像与团队用量相互独立。加入团队不自动公开个人资料，但**加入即自动把用量计入团队**（Token、具名贡献、Agent / 模型分类、费用），没有「只加入、不共享」，也没有个人用量开关。
- 团队只统计 `joined_at` 及之后发生的事件，不回填加入前的个人历史。退出 / 移除后，人从名单和贡献榜消失；已经计入团队的用量留在匿名「历史用户」中，不从总量里扣掉。
- 月度预算、通知机器人、组织层级、企业 SSO 暂不进入首版导航。

## 2. 现状依据与实现缺口

- `web/src/pages/teams/TeamDashboardPage.tsx` 当前仅为不可用占位页。
- 现有全站导航为 TokenBoard / 社区 / 团队，右侧头像进入个人数据和设置；团队页面延续该结构。
- 已有个人指标、趋势、Agent 分布、状态组件与中英文词典可复用。主色为 `#b9f600`，页面背景 `#f5f7f4`，正文 `#111512`。
- `team` 已出现在可见性枚举和排行榜 scope 中，但尚不构成完整的团队成员关系与授权系统。现有聚合任务中的 team scope 分支不能直接视作团队隔离实现。
- 本文在原用户产品方案的 P2 团队方向上单独定义 MVP。以下 P0 / P1 指团队模块内部优先级。

## 3. 功能范围

| 功能域 | P0 首版 | P1 后续 |
| --- | --- | --- |
| 团队身份 | 创建、名称、简介、头像、固定统计时区；账号只能属于一个团队 | 项目归属、团队资料增强 |
| 加入与邀请 | 分享链接、邮箱邀请、登录后确认加入、撤销、到期重新生成 | 入队审批、域名加入 |
| 总览 | Token、活跃成员、可用费用、趋势、贡献列表（当前成员）；脚注说明总量含历史用户 | 目标、周期报告、团队对比 |
| 用量分析 | 日期范围、Agent / 模型分布、工具筛选、统计口径说明 | 项目维度、预算预测、异常分析 |
| 成员 | 搜索、角色、团队同步状态、成员数据抽屉 | 分组、批量管理 |
| 权限 | 固定角色、转移所有权、退出 / 移除 | 自定义角色、企业 SSO |
| 数据操作 | 管理员导出团队聚合数据、基础操作记录 | 审批导出、定期报告 |
| 对外展示 | 私有团队空间 | 公开团队名片、团队榜单（单独授权） |
| 费用管理 | 分开显示已记录费用与估算费用、覆盖率 | 软预算、阈值提醒；不承诺硬限额拦截 |

## 4. 信息架构

```text
全站导航：TokenBoard / 社区 / 团队                 个人头像菜单
                              │
                         /teams 入口
                ┌─────────────┴─────────────┐
             尚未加入                    已有团队
        创建团队 / 待处理邀请          /teams/:teamId
                                            │
                      总览 / 成员 / 用量分析 / 设置

邀请落地页：/teams/invitations/:invitationId
分享链接落地页：/teams/join/:linkId（完整分享链接另携带邀请凭证）
```

- `/teams`：未登录时展示简洁介绍与登录入口，保留 `return_to`；已登录无团队时展示创建入口和待处理邀请；已有团队时进入总览。
- `/teams/new`：独立创建团队页；进入和提交时都检查当前成员关系。已有团队时显示拦截页与「查看我的团队」，不展示可提交的创建表单。
- 总览及用量分析默认今天；筛选依次为今天、7 天、30 天、自定义，右侧明确显示团队时区。自定义可选历史区间，最多 90 个自然日（含首尾），不允许未来日期。
- 四个二级页签使用真实路由：`/teams/:id`、`/members`、`/usage`、`/settings`。
- 日期范围在总览、用量分析和成员统计之间保留，写入 URL；成员页「同步状态」为当前状态，不能混作所选历史周期状态。
- 只有一个团队时显示静态团队身份，不增加没有用途的切换器。

## 5. 页面设计

### 5.0 无团队入口与创建团队页（本次补充）

创建团队采用独立页面。一级导航仍为 TokenBoard / 社区 / 团队；未创建前不展示总览 / 成员等团队内页签。

无团队入口 `/teams`：标题「和同伴一起记录 AI 用量」，主操作「创建团队」；已有待接受邀请时展示邀请列表。页面明确提示「每个账号只能创建或加入一个团队」，不添加通用邀请码框。

创建页 `/teams/new`：

- 页首「返回团队」、标题「创建你的团队」、说明「先给团队一个名字，成员可以稍后邀请」。
- 桌面左侧为单页表单，右侧为随输入更新的团队名片预览；手机表单在前，预览在后。
- 团队名称必填，2–40 个字符；简介选填，最多 120 个字符。名称去首尾空格后再校验，使用字素计数，避免中文 / Emoji 长度提示与提交不一致。
- 头像自动生成团队名首字，不要求上传；后续在团队设置中修改。
- 统计时区默认取账号时区，可在创建时选择；明确说明创建后固定、影响每日边界。
- 不展示用量共享开关。创建成功即按所有者计入全部用量维度，只统计创建时刻起的事件。
- 表单末尾固定文字「每个账号只能创建或加入一个团队，创建后你将成为所有者」，不再要求一个没有独立意义的“同意限制”勾选框。
- 主按钮「创建团队」，次按钮「取消」。空名称 / 单字符 / 纯空格在字段下方解释并聚焦输入；输入保留，不只使用 toast。
- 提交时按钮变为「正在创建…」，冻结表单并防重复点击；失败恢复输入与操作。
- 创建成功进入团队首次使用页，展示团队名、所有者、1 位成员，主操作「邀请成员」、次操作「进入团队」。邀请不属于创建的必填步骤。
- 首次总览走 200 `ready`：尚无事实时展示「等待首次同步」/「此范围没有数据」，**不是**数字 0，也不是整页骨架。骨架只用于删除屏障（202）。加入后切片仍在跑时用非阻断横幅，KPI 保持 empty-state。不填入其他团队的演示用量。

已有团队拦截：显示「你已经有一个团队」，展示当前团队和身份；主操作「查看我的团队」。普通成员 / 管理员需先退出当前团队；所有者需先转移所有权再退出，或解散团队。转移所有权本身不释放名额，不能自动帮用户离开当前团队。

### 5.1 总览

页头：团队头像、名称、简介、私有标记、当前角色；右侧一个主操作「邀请成员」。不提供「我的共享」用量开关入口。

内容顺序：

1. 时间筛选、明确日期区间和「数据更新于…」。
2. 三项指标：团队 Token、活跃成员、已记录费用。每项最多一行解释。
3. 左侧约 2/3 宽度为每日 Token 柱状趋势；右侧为 Agent 构成。手机上下堆叠。
4. 成员贡献列表，默认按本周期 Token 降序，**只含当前成员**。点击姓名打开抽屉，显示其加入后计入团队的指标。
5. 与当前数据相关的状态提示，例如「部分来源没有费用记录」。若所选范围含已退出成员留在队内的用量，用**一条脚注**说明，不把「历史用户」画成贡献榜的一个人。

指标的显示规则：

- 「活跃成员」分子为周期内有有效 model_usage 事件的**当前成员**人数，分母为当前有效成员总数；说明分母时点。已退出者不计入活跃成员。
- 待接受邀请不计入成员数。不再单独展示「共享成员」：在队即计入全部用量维度。
- 费用以 `—` 表示不可用。来源有真实费用时显示「已记录费用」，只有估算时显示「估算费用」，两者不混加。不同币种分别显示。
- 费用旁显示覆盖率：可可靠关联该类费用的有效 model_usage 事件数 / 本周期全部有效 model_usage 事件数；独立费用事件不增加分母。悬浮可查看数量和定义。总量、趋势、Agent / 模型分布**包含**历史用户桶；贡献榜**不包含**。
- Token 总量与分布遵循已有标准化协议，禁止简单相加输入总量和已包含的缓存 Token。

### 5.2 成员

页内切换：「已加入 N」「待接受 N」「邀请链接」。后两项仅管理者可见，待接受只统计定向邮箱邀请；分享链接没有指定收件人，不计入待接受人数。提供姓名 / Handle 搜索；邀请邮箱仅管理者在待接受列表中可见。

已加入表格：头像与昵称、角色、团队同步状态、周期 Token、操作。只列出**当前成员**；已退出者不出现在名单里，也不作为「历史用户」占一行。

- 普通成员只看到团队汇总和已加入名单；看不到邀请邮箱及管理入口。
- 当前成员均可打开个人抽屉，查看加入后计入团队的周期明细。
- 同步状态只反映已计入团队数据的新鲜度，不暴露个人设备列表、主机名、文件路径或账号凭据。
- 「尚无数据」与「同步延迟」分别显示；不能把尚未同步解释为离线。
- 管理者从行内「管理」打开角色与移除操作；所有者行显示固定身份。
- 待接受邀请显示邮箱、拟加入角色、邀请时间、过期时间及撤销 / 重发；重发使旧邀请失效。
- 邀请链接显示创建者、有效期、已加入 / 可加入人数、状态；支持复制、撤销、重新生成。仅成功加入时已加入人数增加，复制和打开链接不增加人数。

成员抽屉约 420 px：身份、加入时间、当前周期、Token 与可用费用、Agent / 模型分布。未采集显示「来源未提供」。不出现「成员未共享此项」。

### 5.3 用量分析

- 沿用全局日期范围，支持全部 Agent 或一个 Agent；模型选项依赖当前 Agent，切换不兼容 Agent 时清空模型筛选。
- 趋势、指标、分布及导出必须来自同一筛选条件与统计版本；不能只更新图表而保留旧数字。
- 在队即共享分类。来源未提供名称时进入「未知分类」合计桶，与真实 Agent / 模型区分。已退出成员的用量进入匿名「历史用户」，计入总量 / 趋势 / 分布，不出现在贡献榜。
- 明细表字段：Agent / 模型、Token、占比、有效事件、费用类型与覆盖率；无支持的数据标记为缺失。
- 页面不展示会话正文、Prompt、回复、代码、仓库路径、密钥或机器信息。
- 管理者可导出 CSV，含当前可见的团队聚合数据、筛选范围、币种、数据截至时间。历史用户以匿名序列 / 标签出现，不还原前成员身份。普通成员仍从个人数据页导出自己的数据。

### 5.4 设置

设置页分两段，避免堆满通用设置：

1. 团队资料：名称、简介、头像、创建时确定的统计时区；所有者 / 管理员可编辑资料。首版时区创建后不可直接修改，避免历史口径漂移。
2. 团队管理：仅展示当前角色允许的转移 / 退出 / 解散操作；最近操作记录只向管理者提供。

**不提供「我的共享」用量授权面。** 公开资料 / 头像仍在个人设置中管理，与是否计入团队用量无关。在队期间全部用量维度自动计入；要停止计入只能退出或被移除（用量留在历史用户桶，人从榜上消失）。

## 6. 关键交互流程

### 创建团队

`创建团队 → 输入名称 / 简介 / 统计时区 → 确认创建 → 团队空总览 → 邀请成员`

- 名称 2–40 字符，简介 0–120 字符；身份使用稳定 team ID，团队名称不充当唯一标识。
- 时区默认取当前账户时区，并说明「影响全体成员的每日统计」。
- 不要求 Logo、不要求成员数量、不强制邀请；创建完可以稍后邀请。
- 提交期间按钮禁用；失败保留输入，错误紧贴字段或表单；重复提交由幂等键处理。
- 所有者创建成功即计入全部用量维度，只统计创建时刻起的事件，不能因创建团队读取加入前的个人历史。

### 邀请与接受

点击「邀请成员」打开对话框，默认「分享链接」Tab，另一个 Tab 为「邮箱邀请」。

**分享链接**：`生成邀请链接 → 复制并发送给同伴 → 同伴打开 → 登录 / 注册 → 确认团队 → 加入团队`。

- 所有者和管理员可生成、复制和撤销链接；普通成员不提供链接管理入口。链接不绑定收件邮箱，持有效链接的已验证账号可以确认加入，无额外管理员审批。
- 首版默认有效期 7 天、最多加入 50 位新成员。生成前可选 1 / 7 / 30 天、1–100 人；这是每条链接的使用次数限制，不是团队人数上限。
- 链接固定授予普通成员角色。需要管理员身份时，由所有者入队后调整，或使用绑定邮箱的管理员邀请。
- 生成后显示链接、到期时间、「已加入 0 / 50 人」和「复制链接」。复制成功有明确反馈；复制失败保留可手动选取的链接，不提前提示成功。系统不代替用户向其他应用发送消息。
- 同一链接可供多人加入；每个账号在该链接下最多成功加入一次，重试或已经在队不消耗次数。退出或被移除后，同一条链接视为已使用，需要新的邀请链接或新的定向邮箱邀请才能再加入；不再根据「上次是被移除」单独禁止分享链接。
- 撤销立即阻止后续加入，已加入成员保留。重新生成先让旧链接失效，再产生新链接；修改有效期 / 人数也按重新生成处理。
- 链接被转发的人也可能加入；生成区用简短说明「持有链接的人可作为成员加入，请分享给你信任的同伴」。到期、撤销、次数用尽时展示相应状态及联系邀请人入口。

**邮箱邀请**：`输入邮箱和角色 → 创建邀请 → 邮件投递 → 收件人打开 → 登录 / 注册 → 确认加入`。

- 保留绑定验证邮箱、单次使用、7 天过期的邀请；一封邀请对应一个成员。登录邮箱不匹配时提示切换账号。
- 「邀请已创建」与「邮件已发送 / 发送失败」分开显示；失败可重试。owner 才能授予 admin，接受时重新校验邀请者权限。

两种方式统一遵守：接受页展示团队名、邀请人、角色；说明加入后将自动计入全部用量维度，且只统计加入时刻起的事件。打开链接不自动入队，必须点击「加入团队」。已在其他团队时显示单团队限制与当前团队入口；已在本团队时显示「你已是成员」。团队解散、邀请者失去邀请权限或账号状态异常时，旧邀请不能继续使用。

### 改角色 / 移除 / 转移

- 管理员只能邀请和移除普通成员，不能提升管理员、管理所有者或其他管理员。
- 所有者可提升 / 降级管理员；转移所有权需选择一个有效成员，再输入团队名确认。成功后原所有者成为管理员。
- 转移过程必须保证任意时刻恰好一个所有者；移除、退出与转移并发时校验当前成员状态。
- 移除普通成员二次确认，展示昵称和「将从成员名单和贡献榜中移除；已计入团队的用量留在匿名历史用户中，个人数据保留」。
- 成员退出后立即失去团队访问权，并从名单 / 贡献榜消失；已计入的用量留在团队历史用户桶。所有者需先转移，若不转移则只能解散团队。
- 解散需输入团队名并再次确认；团队空间、统计（含历史用户桶）和访问一并消失，不删除成员个人账户与原始个人数据。解散与退出不同：退出留量，解散删掉该队全部团队统计。

| --- | --- | --- | --- |
| 看团队汇总和已加入名单 | 是 | 是 | 是 |
| 看当前成员的周期指标 | 是 | 是 | 是 |
| 邀请 / 撤销普通成员邀请 | 否 | 是 | 是 |
| 创建 / 复制 / 撤销成员邀请链接 | 否 | 是 | 是 |
| 邀请管理员 / 修改角色 | 否 | 否 | 是 |
| 修改团队资料 | 否 | 是 | 是 |
| 移除普通成员 | 否 | 是 | 是 |
| 移除管理员 | 否 | 否 | 是 |
| 导出团队聚合 / 查看操作记录 | 否 | 是 | 是 |

## 8. 数据边界与异常状态

- 纳入团队的数据必须同时满足：当前有效成员关系、账号与团队均为 active、事件 `occurred_at >= joined_at`。在队即计入 Token、具名贡献、分类和费用，不再另开授权时间窗或个人开关。
- 延迟上传按事件发生时间判定，而非上传时间；离开之后到达的上传，即使事件发生在旧任期，也不再写入团队统计（具名行或历史用户桶都不写）。重新加入是新的 `joined_at` 和新的当前成员；旧量留在历史用户桶，不重新挂到此人。
- 退出 / 移除：人立即失去访问并从名单、贡献榜消失；已计入的用量合并进该队匿名「历史用户」，总量 / 趋势 / 分布仍包含它们。账号注销若仍在队，先按退出合并，再删账号；合并后无法再按人从历史桶扣减。
- 解散：该队统计（含历史用户桶）全部删除，个人事件与个人看板保留。与退出不同。
- 当前成员的隐私删除只重建该人具名行；不试图拆开已经匿名的历史用户桶。
- 已下载到用户本地的文件无法追回，导出前说明这一点。
- **单团队约束由服务端和数据库共同保证**：创建与接受邀请走同一原子名额占用流程。当前关系表以 `user_id` 为唯一键。**不保存已结束的成员关系作为产品记录**；退出删除当前占用与当前成员行。不能对成员表的全部 `user_id` 做唯一约束而阻止退出后再加入。
- 创建时，将团队、所有者关系和名额占用放在同一事务中；两个页面同时创建、创建与接受邀请并发、同时接受不同团队邀请，仅一个成功，失败事务不得留下无所有者团队。冲突返回 `409 TEAM_MEMBERSHIP_EXISTS` 与有权查看的当前团队入口。
- 待接受邀请不占名额，可以同时收到多封；接受其一后，其余邀请仍需遵守单团队限制。正常退出 / 被移除 / 解散生效后才能重新创建或加入。重试同一成功请求应返回原结果，不创建第二个团队。
- 邮箱与分享链接共用成员写入事务和数据库名额约束；多人同时使用链接的最后一次名额时，最多一个成功，失败不能增加使用次数。未登录、预览、复制、幂等重试都不扣次数。同一链接对同一账号只成功加入一次，与成员行是否还在无关。
- 比较上周期使用同样口径。若当前成员集合变化或上期无可比值，显示「暂无可比数据」，不伪造 +100%。
- 排名相同 Token 使用相同名次；其次按稳定 ID 排序以避免抖动。贡献榜只含当前成员；历史用户不排名。

| 状态 | 展示 | 可采取的操作 |
| --- | --- | --- |
| 未加入 | 简介、创建入口、待处理邀请 | 创建 / 接受邀请 |
| 已创建但仅本人 | 「团队已创建，邀请同伴一起记录」 | 邀请 / 稍后处理 |
| 已加入尚无有效数据 | 200 ready + empty-state「等待首次同步」或「此范围没有数据」，不是数字 0、不是骨架 | 查看个人同步页 |
| 加入切片仍在同步 | 200 + 非阻断横幅；KPI 仍 empty-state | 等待；不整页刷新 |
| 筛选无结果 | 「此范围没有数据」 | 清除筛选 |
| 部分费用不可用 | 有效值 + 费用覆盖率 | 查看口径 |
| 同步数据较旧 | 数据截至时间 +「可能仍有待补传」 | 查看成员状态 |
| 页面请求失败 | 错误说明；非隐私撤回场景可保留注明时间的旧值 | 重试 |
| 邀请发送失败 | 待接受记录标记邮件未送达 | 重试发送 / 撤销 |
| 分享链接到期 / 已撤销 / 次数用尽 | 明确说明当前状态，不显示加入按钮 | 联系邀请人；管理者可重新生成 |
| 权限已改变 | 关闭失效抽屉并提示身份变化 | 返回总览 |
| 已移除 / 已解散 | 不再展示团队数据 | 返回团队入口 |

## 9. 视觉与交互规范

- 延续现有浅灰绿背景、白色面板、黑色文字、荧光绿主操作，不额外引入一套侧栏导航。
- 画布最大宽度沿用现有 1360 px；页内间距 24 px，模块 16–24 px；卡片圆角 14 px，输入与按钮 6–10 px。
- 标题 28–32 px、正文 14 px、说明 12–13 px；数值使用等宽数字。大数字控制在团队 Token / 活跃成员 / 费用等少数几项，避免复制个人页全部十项指标。
- 成员详细信息使用右侧抽屉；创建使用独立页面，邀请使用居中对话框；销毁操作单独确认。
- 对话框管理焦点、Esc 关闭、返回触发控件；表单错误保留输入；成功后更新数据并显示简短反馈。
- 360 px：指标两列、趋势和分布纵向、成员行转为紧凑卡片，详情变全宽；所有核心操作触控目标至少 44 px。
- 错误 / 无数据 / 离线不只靠颜色区分；图表数值可用键盘或触摸查看；支持减少动画偏好。
- 中英文使用现有 locale 机制，角色、状态、动态复数与日期统一翻译；不在中文界面混用英文操作词。

## 10. 开发拆分与验收

建议依次交付：

1. 团队 / 成员 / 邀请的模型、服务端权限、创建和加入流程。
2. 当前成员关系驱动的静态汇总、退出合并进历史用户、导出保护。
3. 总览、用量分析、成员抽屉、中英文与响应式适配。

核心模型：`teams`、当前-only `team_memberships`、`user_current_teams`、`team_invitations`、`team_audit_events`；静态日表与历史用户桶见静态物化方案。`team_sharing_grants` 不再作为用量资格来源。沿用现有用户身份和采集事件，不复制个人账号。以下为已与技术方案对齐的计划接口：

- `GET /api/v1/me/team`，`POST /api/v1/teams`
- `GET/PATCH /api/v1/teams/:id`，`GET /api/v1/teams/:id/members`
- `POST /api/v1/teams/:id/invitations`，`POST /api/v1/team-invitations/:invitationId/accept`；邀请详情与接受均校验登录用户的验证邮箱。
- `GET/POST /api/v1/teams/:id/invite-links`，以及链接的 share-url / revoke / regenerate 操作；`POST /api/v1/team-invite-links/:linkId/preview|accept` 用于凭链接预览和加入，不绑定特定收件邮箱。
- `GET /api/v1/teams/:id/analysis`，统一返回同一快照的指标、趋势与构成；成员周期详情与导出引用同一 snapshotId。
- `POST /api/v1/teams/:id/exports`。`PATCH /api/v1/teams/:id/my-sharing` 不再作为用量授权面；过渡期若仍接受该字段则忽略，不改变资格。
- 独立的 revoke invitation、role change、remove、leave、transfer、dissolve 操作接口；统一幂等和并发版本校验。

上线前必须验证：

- 未登录跳转后能回到原邀请；邮箱不匹配、过期、撤销和重复接受均正确。
- 链接可复制分享并供多个账号确认加入；邮箱与链接入口清晰，管理权限一致。次数上限、最后名额并发、旧链接失效、同一链接退出后再用返回已使用，均正确。重入队使用新链接或新邮件邀请。
- 普通成员无法直接调用管理 API；管理员无法升级自己或管理所有者。
- 不同 team ID 的查询、导出、缓存与榜单无越权；不能直接复用旧 team 枚举分支完成隔离。
- 私密个人资料不因加入团队而公开；公开资料也不会替代团队成员名单。
- 创建 / 加入即计入全部用量维度；只统计 `joined_at` 起的事件，不回填加入前个人历史。
- 非成员不能看团队页。退出后贡献榜无此人、总量含历史用户。后台导出遵守同一当前成员与句柄版本。
- 日期、Agent、模型变更后图表、列表、总量与导出一致；缺失费用不按 0 计。
- 退出、移除、解散、注销及所有权转移并发保持权限和唯一所有者正确。退出留量；解散删该队统计。
- 任何角色都不能同时属于两个团队；创建 / 接受邀请的并发竞争、旧页面提交、幂等重试均不可绕过约束。所有权转移后，原所有者仍占用当前团队名额，须退出后才能加入另一个团队。
- 创建页空值 / 纯空格 / 字符长度校验、取消后返回入口、失败输入保留、无用量共享开关、创建成功仅一个成员、已有团队拦截均正确。
- 360 / 736 / 1024 px、键盘对话框、中文 / 英文状态文案通过验收。

## 2026-09-12：成员关系、自动共享与退出留量

与静态物化方案对齐的产品锁定（不再重开）：

1. 每个账号同时最多一个团队。名额在当前占用表上。
2. 不保存已结束的成员关系作为产品记录。退出 / 移除删除当前占用。
3. 在队 = 自动共享 Token、具名贡献、分类、费用。无个人用量开关。
4. 只统计加入时刻起的事件。加入时允许回填已存且时间 ≥ 加入时刻的事实，不回填加入前个人历史。
5. 退出 / 移除：人从名单和贡献榜消失；已计入用量合并进匿名「历史用户」，按日保留以便 7d / 30d / 自定义窗口。
6. 再加入视为新人；旧量不重新挂回。
7. 离开之后到达的上传不再写入团队统计。
8. 解散删除该队全部团队统计（含历史用户）；个人数据保留。
9. 账号删除若仍在队则先按退出合并；所有者须先转移或解散。
10. 暂停仍是当前成员，统计保持具名，直到退出 / 移除。
