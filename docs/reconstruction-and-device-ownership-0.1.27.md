# 0.1.27：历史重建、设备归属和动态最低版本

状态：功能分支实现并验证，尚未发布。旧版本发布表、安装包校验与下载流程继续复用。本说明替代旧方案中“首次安装也只采当天”“历史贡献固定归首次接收账号”“必须重装才能重建”的约定。

## 版本触发与手动重建

软件版本 `0.1.27` 是首次重建发布点，配置在 `local_store/pipeline/reconstruction.rs` 的 `REBUILD_RELEASES`。以后只有需要重新计算 raw 的发布才加入该列表，保留旧发布点以覆盖跳版本升级。使用 SemVer 数值比较，没有独立 rebuild_version。

启动时检查当前软件版本范围内是否存在尚未完成的重建发布点。首次新库也会触发。`schema_meta.extra.rebuild` 保存 active、targetVersion、completedVersion 和 discovered；重建完成才记录完成版本。中断后继续已有进度，不再次清库。普通版本更新及普通启动恢复已提交的游标。

设置新增“重建数据”，展示来源扫描进度，并在清空前由用户确认。自动重建和手动重建共用同一执行路径：

1. 手动操作锁住上传调度，等待已发出请求结束；采集运行时取得写锁，等待正在执行的采集和本地统计结束。
2. 单 SQLite 事务清空 events、processing_tasks、collection_sources、bucket_entity_state 和四类 metrics。
3. 保留设备签名密钥、匿名化密钥、登录和设置；模型/技能维度保留，避免策略缓存中的维度 ID 悬空。
4. 重新发现来源。每个来源在 observed_boundary_json 中保存 `_rebuild_pending`；游标、事件及该标记同事务提交。
5. 来源到达 EOF 后恢复当天准入。全部来源扫描完且本地小时/日/月处理结束后，标记本次重建完成。读取失败或统计 blocked 不会误报成功。

采集仍为多个 worker 并行读取、单 SQLite writer 提交；上传和本地统计独立消费已入库事件。历史事件按原 occurred_at 进入小时/日/月桶，不改成重建当天。普通采集只首次准入北京时间当天记录，已准入事件允许跨日重试。

本地事件仍按 **created_at 保留 14 天**。历史记录今天重建入库，其明细保留至今天起 14 天；长期聚合不会因此删除。无法从 raw 恢复已删除的原始文件。无原生时间时继续采用同流前序原生时间、再文件 mtime 的既定顺序，不填 1970。

## 历史上传与幂等

v2 请求增加可选布尔字段 reconstruction。客户端上传包含早于正常接收窗口的已准入事件时设置 true；该字段包含在设备签名保护的请求正文中。服务端因此允许历史 occurred_at，仍校验未来时间、事件结构、内容哈希、登录、设备签名和绑定版本。

普通首次上传仍受“北京时间今天及此前 14 个自然日”接收窗口约束。重复事件先按 `(installation_id,event_id)` 查重：同 hash 返回 duplicate，不再创建统计任务；不同 hash 冲突拒绝。请求 ID、软件版本、登录账号和重建次数都不参与事件身份。

服务端事件身份与完成状态长期保留，**不执行客户端的 14 天明细删除策略**，因此隔月再次重建仍可去重。显式数据删除是另一项业务操作，不能与解绑混用。

## 数据属于设备

实际迁移：`server/internal/migrate/migrations/0014_device_owned_telemetry.sql`，在 db/migrations 下有镜像。事件、四类 metrics 和 bucket_entities 删除 user_id；唯一键和查询索引以 installation_id 为设备边界。既有设备、公钥、模型、技能和发布表继续复用。

四个 `bound_telemetry_*_metrics` SQL 视图通过 installations 关联当前有效绑定，不创建新的实体表、不复制统计。用户可绑定多个设备，一个设备同一时刻只能归一个用户：

- active / disabled 保留绑定；revoked 表示解绑，设备事实与统计保留。
- 已绑定 A 时，B 不能直接抢占。A 解绑后，B 可用登录授权和设备私钥证明重新绑定同一 installation_id。
- 解绑时 A 的查询不再包含此设备；绑定 B 后，B 的查询包含设备全部历史。绑定事务同步更新用户窗口分数，标记受影响日期并通知排行榜/社区异步更新。
- 暂停采集/上传不等于解绑，暂停设备的既有统计仍计入用户。

注册/绑定码恢复已解绑设备时必须证明持有私钥。注册签名串为 `tokendance-device-binding\nregister:<user_id>\n<公钥小写hex>\n<Unix秒>`；绑定码路径使用 `claim:<规范化绑定码>`。签名 Ed25519，hex 编码，时间偏差最多五分钟；公开公钥不足以认领历史。已有 rebind 路由继续验证完整设备请求签名。

迁移仅重算已存在事件的派生统计，不从旧 SQLite 库搬数据。客户端历史来自 harness raw。迁移前后的事件 ID 不变，保留服务端已接收身份。

## 服务端动态更新策略

公开接口：`GET /v1/update-policy`，通过现有部署前缀访问，响应 `Cache-Control: no-store`。

```json
{"minimumVersion":"0.1.27","refreshAfterSeconds":60}
```

- `TOKENDANCE_MIN_CLIENT_VERSION`：默认最低软件版本；空字符串关闭强制要求。
- `TOKENDANCE_UPDATE_POLICY_FILE`：可选服务器 JSON 配置路径。配置此路径后每个请求重新读取文件；原子替换文件即可实时生效，不重启服务。文件内容与上述 JSON 一致，服务端固定返回 60 秒轮询周期。
- 配置非法或不可读取返回 503。客户端请求失败时撤销强制提示；最后有效要求也会在 90 秒后失效，离线不阻断使用。

桌面启动、每 60 秒及网络恢复时获取策略。低于最低版本显示不可关闭的更新提示并暂停新云同步，本地采集继续。下载安装包不阻塞策略轮询。没有满足最低版本的有效安装包时明确提示尚未发布，避免安装一个仍低于门槛的版本。

发布顺序：先发布兼容服务端及可校验的桌面安装包，再提高最低版本；只有支持该策略的客户端才能展示此提示，已发布的旧二进制不会自动获得新逻辑。正式部署只允许干净 main 且 HEAD 等于 origin/main，并记录完整 SHA。
