# 首次扫描与实时采集吞吐修复

## 问题与实现

| 问题 | 修复 |
| --- | --- |
| JSONL 完整大行超过 1 MiB 批预算后反复读取同一位置 | 字节和时间预算在记录边界生效，允许当前合法记录读完；沿用 4 MiB 单行上限。超限记录分段跳过，丢弃状态随游标持久化，直到换行才恢复解码；正常未完成尾行保持原游标。 |
| 每 5 秒只发出四个批次 | 四个常驻异步 worker 各自提交、领取下一批，阻塞读取和解码交给 blocking pool。全局并发 4、每 harness 并发 2、每流并发 1，空出的槽位立即补充。 |
| EOF 与未完成尾行重复占用采集名额、反复写库 | JSONL 追平或无进展后退出就绪队列，仅在源文件变化后唤醒。SQLite 同时检查主库和 WAL；无变化时 30 秒保底查询，变化则提前唤醒。 |
| 历史文件遮挡活跃文件 | 新来源按修改时间降序注册；同 harness 内优先今日活跃来源、同级按上次调度顺序轮转。每个 harness 每八次领取保留一次公平调度，让历史积压也能推进。 |
| 每轮重复遍历、重复注册已知来源 | 来源身份缓存按 `(harness_id, source_key, stream_key)` 区分，避免合并同一 SQLite 的不同流。新增来源每 64 个用一个事务注册，已有检查点保持不变。 |

## 唤醒与补偿

- 文件系统通知标记来源变化；新增、删除、重命名触发目录发现失效，最小发现间隔为 2 秒。
- 每秒执行独立维护调度；通知可提前触发元数据检查，检查最小间隔为 1 秒。
- 即使通知丢失，每 5 秒仍检查已知来源的元数据；每 30 秒重新发现目录，覆盖启动时不存在的根目录和监听失败的情况。
- 文件 I/O 不持有 SQLite 写事务；发现时的文件元数据读取不持有采集队列锁。
- 单 writer 原有的 5 秒租约回收和保留期补偿继续运行；新管线不再每拍清理旧版明细库。
- worker 每批检查全局暂停和 harness 开关；错误等待重试，避免失败来源占满连续队列。
- 日志新增来源总数、未追平来源数和失败次数；这些是调度诊断值，不作为上传成功或全量完成的证明。

## 数据口径与边界

吞吐优化本身不改变事件身份和原子提交。0.1.27 同时引入版本触发的全量重建与历史上传，最终行为以 [重建实施说明](reconstruction-and-device-ownership-0.1.27.md) 为准。

文件修改时间只用于调度优先级，不能用它判断文件内所有事件都过期。历史文件仍按流解码，保留会话身份、前一条有效时间、累计用量等上下文；普通采集首次入库只收北京时间当天事件；全量重建允许历史事件。没有实现按 mtime 直接跳到 EOF 的捷径，避免漏算跨天会话的新用量。

1 MiB / 256 条 / 50 ms 的默认批预算保留；完成当前合法大行时允许超过字节与时间预算。超限记录通过有界丢弃游标推进，避免无限分配内存或把超限行的后半截识别成新事件。

## 验证

- 桌面 Rust 全量：236 项通过，8 项按要求忽略（其中包含下面已单独运行的本机只读诊断）。
- 回归覆盖：1–4 MiB 行、超限行跨批丢弃与追加、未完成尾行、跨 harness 公平调度、每 harness 历史公平槽、空闲后追加、SQLite WAL 变化、开关暂停恢复、重启保留检查点、注册事务回滚、真实文件系统创建通知。
- 合成调度用例：192 个文件、384 个批次，在一次发现之后连续处理，观测约 220 ms。记录是小型合成数据，这不是完整历史库的吞吐或剩余时间估算。
- 本机只读诊断已验证完整大行可以推进。只读源文件和本地库，不保存事件、不提交真实游标、不输出会话内容或来源路径。

```powershell
# 显式设置 TOKENDANCE_PIPELINE_PROBE_DB 为本机事件库路径后：
cargo test --manifest-path collector/apps/desktop/src-tauri/Cargo.toml --lib local_large_line_read_only_probe --locked -- --ignored --nocapture
```
