# 头像与首页排行榜缓存

## 行为

- 首页请求公开榜单前 100 名，最多渲染 100 行；完整列表继续保留分页和登录用户排名。个人统计仍通过需要登录的接口获取，不放入公共缓存。
- 公共榜单和社区统计使用 `public, max-age=30, must-revalidate`，与页面 30 秒刷新周期一致；提供内容 ETag，未变化时返回 304。失败响应不缓存。
- 首页将四个周期的公开榜单和社区统计分别保存到本地，打开/返回页面同步显示已有内容，再后台更新；刷新失败保留内容。仅保存公开展示字段，按部署路径隔离，不包含个人数据。北京时间跨天后不再展示旧快照；损坏或不可用的浏览器存储不阻塞网络加载。
- 用户头像最长边 256px，等比缩小，不放大。普通照片编码为 JPEG quality 80，透明图使用 PNG；已经足够小且体积更小的原图直接复用。
- 新上传头像在完成校验后生成对象存储缩略图，原始上传保留用于校验和重试。账号删除同时清理缩略图。
- 旧头像无需重新上传：首次读取时压缩，压缩结果进入进程内 LRU。旧头像读路径不写对象存储，避免与账号删除竞争；进程重启或缓存淘汰后会再次压缩。
- 图片内容缓存最多 256 张 / 16 MiB；同一图片并发加载合并，仍在每次请求时检查当前头像及账号状态。
- 浏览器头像缓存使用 `private, max-age=604800, immutable` + ETag，7 天内直接复用。更换头像产生新对象 URL，移除或停用后的榜单刷新会去除旧 URL。服务端对新的网络请求仍检查可见性并返回 404，但浏览器中已缓存的旧 URL 最多可继续读取 7 天，不再保证旧 URL 即时撤回。
- Nginx 对上述公共接口保留应用缓存策略，其余 API 继续 `no-store`。内置头像缓存一天，带 hash 的 JS/CSS 继续缓存一年。
- 前三名头像高优先级，列表非前三名懒加载。
- 内置四张默认头像使用 256px JPEG 派生资源，兼容已有资料里的 PNG URL。原图保留；可在 `server/` 下运行 `go run ../tools/images/compress-default-avatars.go` 重新生成。

## 复核与验证

- 复核公开榜单不接受客户端身份、首页不混入个人排名，内容 ETag 随数据变化而变化。
- 测试覆盖透明度、尺寸、体积缩减、像素上限、历史头像、并发去重、LRU 容量、删除后网络请求被拒绝、7 天缓存策略、304 空响应、失败不缓存、首页 100 行上限，以及本地缓存首次展示、后台更新、周期隔离、跨天清理、离线保留和存储异常。
- 补充账号删除缩略图的 MySQL 集成断言；没有在共享开发库运行重置型测试。
- 前端 typecheck 和生产构建通过。全量前端 185 项中 183 项通过；另外两项在原始 `origin/main`（`1b95453`）上也失败，分别是 onboarding 旧文案和个人面板旧费用格式断言，未为本次改动放宽断言。
