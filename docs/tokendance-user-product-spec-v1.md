# TokenDance 用户产品功能方案 v1

> 状态：产品定义稿  
> 范围：用户注册登录、个人数据、公开资料、查询与隐私控制  
> 本轮边界：只定义产品功能并制作 Mock UI，不接真实数据库，不改线上站点

## 1. 产品目标

TokenDance 当前已经具备公开 Token 排行榜和数据上报能力。用户系统的目标不是再做一个通用账户中心，而是完成三件事：

1. 把 Collector 上报的数据稳定归属到具体用户和设备。
2. 让用户看到比公开排行榜更完整的个人数据，并能解释数据来源和准确度。
3. 允许用户控制公开范围，同时提供面向社区的搜索、公开主页和比较能力。

核心闭环：

`访客浏览 → 邮箱注册/登录 → 首次建档 → 绑定 Collector → 查看个人数据 → 控制公开范围 → 进入排行榜与社区查询`

## 2. 用户角色与权限

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 访客 | 浏览公开排行榜、搜索公开用户、查看公开主页 | 查看任何私有明细、设备信息或未公开数据 |
| 注册用户 | 查看完整个人数据、管理公开资料、设备和隐私、参与排行榜、导出自己的聚合数据 | 查看其他用户的私有数据 |
| 团队成员（后续） | 查看团队共享指标和团队榜单 | 默认查看成员个人私有明细 |
| 运营管理员（非本轮） | 处理举报、异常榜单和账号状态 | 读取 Prompt、回复、代码正文等禁止采集内容 |

## 3. 注册与登录

### 3.1 登录方式

首期采用 **邮箱账户登录**。登录后的 Session、受保护页面跳转和 `return_to` 处理参考 `flux_port/app/chatgpt-auth.ts`，但身份因子改为邮箱：

- 登录使用邮箱 + 密码。
- 注册使用邮箱、邮箱验证码和密码，邮箱验证完成后创建账户。
- 忘记密码通过邮箱验证码重置，不提供密保问题。
- 首次登录后进入首次建档。
- 已登录用户访问受保护页面时直接进入；未登录用户保留 `return_to`，登录后回到原页面。
- 支持主动退出、Session 过期重新登录、退出其他设备和多设备 Session 失效。
- P0 不提供 ChatGPT、GitHub 等第三方登录，后续可作为可选绑定方式。

### 3.2 首次建档

首次登录后必须完成以下字段：

- 公开昵称：可修改，排行榜和公开主页使用。
- 唯一 Handle：例如 `@maxbauer`，用于公开主页 URL。
- 头像：默认生成品牌色占位头像，用户可以上传替换。
- 时区：影响个人日历和每日统计边界。
- 排行榜参与：默认关闭，用户明确开启后才进入公开榜单。
- 数据可见性：私密 / 公开摘要；团队可见在团队功能上线后增加。

昵称与 Handle 不使用邮箱自动公开。邮箱只作为账户字段，不进入排行榜接口。

### 3.3 账户状态

| 状态 | 产品表现 |
| --- | --- |
| `email_unverified` | 已提交注册，等待完成邮箱验证 |
| `new` | 已完成登录，等待首次建档 |
| `active_private` | 已建档，数据仅本人可见 |
| `active_public` | 已建档并参加公开排行榜 |
| `suspended` | 暂停公开和数据接收，允许用户查看说明 |
| `deletion_pending` | 进入撤销窗口，停止公开展示和新设备绑定 |

## 4. 用户个人数据页

### 4.1 总览 `/me`

页面首先回答“我最近用了多少、产生了多少代码、花费和效率如何、数据来自哪里”。

核心模块：

- 时间范围：今天、7 天、30 天、全部。
- 核心指标：预估费用、总 Token、生成代码行、单行 Token、输入上下文、输出 Token、缓存命中率、总时长、总消息数、用户消息数。
- 排名信息：当前排名、排名变化、百分位；未参加公开榜单时显示“仅自己可见”。
- Token 趋势：按日展示输入、输出和缓存 Token，可按模型和 Agent 筛选，并切换总量与结构。
- Agent 构成：Codex、Claude Code、Cursor 等占比和趋势。
- Skill 排行榜：按调用次数展示个人最常使用的 Skill、使用天数和变化趋势。
- 活跃日历：与首页 Token Activity 视觉保持一致。
- 最近同步：最后一批上报时间、待同步数量、异常提示。

### 4.2 数据明细 `/me/activity`

仅展示聚合后的安全明细，不展示 Prompt、回复、代码正文、绝对路径和工具参数。

支持筛选：

- 时间范围与自定义日期。
- Agent、模型、设备、事件类型。
- 会话、轮次、工具、Skill、代码量等指标。
- 同步状态：正常或延迟同步。

结果字段建议：发生时间、Agent、模型、Token、会话数、轮次、来源设备。支持导出自己的 CSV。

### 4.3 数据构成 `/me/breakdown`

- 按 Agent：Token、会话、活跃天数、最近使用。
- 按模型：Token、输入/输出比例、使用次数。
- 按 Skill / 工具：调用次数、使用天数、趋势。
- 按设备：贡献占比和最后在线时间。
- 按 Skill：调用次数、使用天数、趋势和个人排名。

### 4.4 里程碑 `/me/achievements`（P1）

- 首次上报、7 日连续活跃、100M Token 等可解释里程碑。
- 支持生成公开分享卡，但分享卡只包含当前公开字段。
- 不设计模糊的“生产力总分”，避免误导比较。

## 5. 公开用户主页

路由：`/u/:handle`

公开字段由用户单独控制，首期建议包括：

- 头像、昵称、Handle、个人简介。
- 当前公开排名、总 Token、活跃天数、连续活跃。
- 公开时间范围内的 Token 趋势和活跃日历；Token 趋势支持按模型和 Agent 筛选。
- Agent 构成与公开成就。
- 用户允许公开的 Skill 排行榜。
- 数据更新时间和统计口径说明。

默认不公开：邮箱、设备名称、安装 ID、私有 Skill 名称、项目或仓库标识、会话明细。

公开主页提供“复制链接”和“加入比较”；P1 再提供关注功能。

## 6. 查询与发现

### 6.1 全站搜索 `/explore`

一个搜索入口覆盖：

- 用户：昵称、Handle。
- 团队：团队名（团队功能上线后开放）。
- Agent / 工具：例如 Codex、Claude Code、Cursor。
- Skill：只搜索允许公开且达到最小样本量的 Skill。

搜索结果按类型分组，不把所有结果混成一张表。支持键盘快速搜索，点击用户进入公开主页。

### 6.2 排行榜高级查询 `/leaderboard`

在现有排行榜上增加：

- 时间：今天、7 天、30 天、全部、自定义周期。
- 指标：Token、会话、轮次、工具调用、Skill 使用、AI 代码量。
- Agent：全部或单个 Agent。
- 范围：全球、我关注的、团队（后续）。
- 搜索：昵称或 Handle。

筛选条件进入 URL Query，便于分享和复现查询。

### 6.3 用户比较 `/compare`

- 最多选择 3 个公开用户。
- 同一时间范围和同一指标口径下比较。
- 对比 Token 趋势、Agent 构成和活跃天数。
- 隐藏项直接显示“该用户未公开”，不能用零值代替。

### 6.4 我的数据查询

登录用户可以在 `/me/activity` 对自己的聚合数据做更细筛选。全站搜索和个人数据查询使用不同权限边界，公共搜索永远不能返回个人私有字段。

## 7. 设备、数据与隐私

### 7.1 Collector 设备 `/settings/devices`

- 显示设备别名、操作系统、Collector 版本、最后在线、同步状态。
- 新设备使用一次性绑定码或深链绑定到当前账户。
- 支持改名、暂停同步、撤销设备。
- 撤销后服务端拒绝新批次；历史数据是否删除由用户另行选择。

### 7.2 公开范围 `/settings/privacy`

- 是否参加公开排行榜。
- 公开资料字段开关。
- 指标级可见性：Token、活跃日历、Agent 构成、成就。
- 公开主页预览。
- 请求删除服务端数据与注销账户。

任何从私密改为公开的操作都应展示将公开的字段清单；从公开改为私密立即从公开查询和排行榜移除。

## 8. 后端功能边界

首期可以用 Mock Repository 实现，保持接口不依赖具体数据库。

### 8.1 服务模块

| 模块 | 职责 |
| --- | --- |
| Identity | 邮箱注册、邮箱验证、密码登录、密码重置、Session、首次建档状态和账户状态 |
| Profile | 昵称、Handle、头像、简介、时区 |
| Privacy | 排行榜参与、字段可见性、公开主页投影 |
| Personal Analytics | 读取聚合数据，生成个人总览、趋势和构成 |
| Search | 公开用户、Agent、Skill 的索引和分组搜索 |
| Leaderboard Query | 时间、指标、Agent 和用户范围筛选 |
| Comparison | 在同一口径下比较多个公开用户 |
| Device Binding | Collector 设备绑定、撤销、状态和最后同步 |
| Export | 导出当前用户自己的聚合数据 |

### 8.2 建议 API（Mock 阶段）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/auth/session` | 当前登录状态与首次建档状态 |
| POST | `/api/auth/register` | 邮箱、验证码和密码注册 |
| POST | `/api/auth/verify-email` | 验证邮箱验证码 |
| POST | `/api/auth/login` | 邮箱和密码登录 |
| POST | `/api/auth/password/forgot` | 请求密码重置验证码 |
| POST | `/api/auth/password/reset` | 使用验证码设置新密码 |
| POST | `/api/auth/onboarding` | 保存首次建档信息 |
| POST | `/api/auth/logout` | 退出当前 Session |
| GET / PATCH | `/api/me/profile` | 读取和修改个人资料 |
| GET | `/api/me/summary` | 核心指标和排名摘要 |
| GET | `/api/me/trends` | Token 与活跃趋势 |
| GET | `/api/me/breakdowns` | Agent、模型、Skill、设备构成 |
| GET | `/api/me/activity` | 个人安全聚合明细查询 |
| GET | `/api/me/devices` | 设备列表和同步状态 |
| POST | `/api/me/devices/bind-code` | 创建短时绑定码 |
| POST | `/api/me/devices/:id/revoke` | 撤销设备 |
| GET / PATCH | `/api/me/privacy` | 可见性设置 |
| GET | `/api/search` | 公共分组搜索 |
| GET | `/api/leaderboard` | 排行榜高级查询 |
| GET | `/api/users/:handle` | 公开用户主页 |
| GET | `/api/compare` | 公开用户比较 |
| POST | `/api/me/export` | 创建个人数据导出任务 |

所有 `/api/me/*` 接口只使用服务端 Session 解析出的用户 ID，不接受客户端传入 `user_id` 作为权限依据。

- `SessionUser`

- `PersonalSummary`
- `MetricSeries`
- `AgentBreakdown`
- `ActivityRow`
- `CollectorDevice`
- `PublicProfile`

## 9. 隐私与安全规则

1. 登录身份和数据上报身份必须在服务端绑定，客户端不能任意指定归属用户。
2. 公共接口只读取 Public Profile 投影，不从完整用户对象删字段后直接返回。
3. Prompt、回复、Reasoning、代码正文、绝对路径、凭据永不进入产品查询接口。
4. Handle 唯一且大小写不敏感，历史 Handle 需要短期保留跳转，避免链接劫持。
5. 设备绑定码短时有效、单次使用，并绑定当前 Session。
6. 排行榜公开是明确同意，默认关闭。
7. 数据删除需要异步任务状态和审计结果，不能只做前端提示。
8. 密码只保存强哈希摘要；邮箱验证码短时有效、单次使用并限制发送频率和尝试次数。
9. 中英文使用同一字段与权限定义，语言切换不能改变查询口径。

## 10. MVP 优先级

### P0：形成完整用户闭环

- 邮箱注册、验证、密码登录、密码重置、退出、Session 与首次建档。
- 中英文界面切换，首期覆盖所有用户侧页面和错误状态。
- 个人总览、十项核心指标、可按模型/Agent 筛选的趋势、Agent 构成、Skill 排行榜和活跃日历。
- 公开资料、公开主页和排行榜参与开关。
- Collector 设备列表、绑定与撤销。
- 全站用户搜索和排行榜高级筛选。
- Mock Repository 与 API 契约。

### P1：增强查询与社区价值

- 个人活动明细筛选与导出。
- 用户比较、里程碑、分享卡。
- Skill 搜索与最小样本量保护。

### P2：团队与社交

- 团队空间、团队榜单、邀请和角色。
- 关注、收藏查询、公开动态。
- 异常提醒和同步通知。

## 11. P0 验收标准

1. 访客可以浏览公开榜单，但访问 `/me` 会进入邮箱登录。
2. 首次登录必须完成建档，且排行榜参与默认关闭。
3. 用户可以在一个页面看清预估费用、总 Token、生成代码行、单行 Token、输入上下文、输出 Token、缓存命中率、总时长、总消息数和用户消息数。
4. Token 趋势可以分别按模型和 Agent 筛选，个人页和公开主页均包含 Skill 排行榜。
5. 用户关闭公开后，公开主页、搜索和排行榜立即不再返回该用户。
6. 公共搜索不会返回邮箱、设备、安装 ID 或私有数据。
7. 用户撤销设备后，新上报批次被拒绝，页面状态同步更新。
8. 查询条件可通过 URL 复现，空结果、加载失败和权限不足均有明确状态。
9. 所有原型页面均可以在中文和英文之间切换。
10. Mock 数据替换为真实 Repository 时，前端 API 契约不需要改变。

## 12. 本轮 UI 原型范围

本地 UI 原型覆盖：

1. 邮箱注册与登录。
2. 首次建档。
3. 用户个人数据总览。
4. 全站搜索与高级查询。
5. 公开用户主页。
6. 隐私与设备设置。
7. 全局中英文切换。

这些原型仅用于确认信息架构和视觉方向，不代表真实接口已经实现。
