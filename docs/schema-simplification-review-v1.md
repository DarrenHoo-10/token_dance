## 1. 删除的六张表

| 原表 | 处理 | 原因及替代方式 |
| --- | --- | --- |
| fact_versions | 删除 | 普通完成明细固定 revision=1；有可靠原生修订时使用保留期内的旧事件，不再持久化本地递增版本账。 |
| event_identity_ledger | 删除 | 本地不提供原库任意历史重放；清理事件保留来源游标，永久逐事件身份记录不再是当前需求。 |
| projection_generations | 删除 | 当前要求是三个异步统计消费者，没有同时维护多套历史统计版本的需求。 |
| projection_heads | 删除 | 没有多套统计版本就不需要一张表指向当前版本。 |
| projection_rebuild_checkpoints | 删除 | 不实现常驻的历史影子回放系统；14 天明细本身也不足以重建全部历史。 |
| ingest_diagnostics | 删除 | 来源表保存忽略记录数、最近原因及到期未完成事件数，任务表保存最近失败码；详细排障使用已有日志。无需再维护逐记录诊断库。 |

此前已经合并来源与游标表，删除 data_owners、sync_targets 和通用 source_generation，本次不恢复。

## 2. 保留的十张表逐张说明

| 表 | 必须解决的问题 | 本次收简或保留依据 |
| --- | --- | --- |
| collection_sources | 一个独立读取流的定位、调度和原子断点续读 | 来源、游标、解析基线同一行；忽略计数与游标同事务。不单建 checkpoint、重置代次或诊断表。 |
| events | 本地细节与小时、日、月、上传四个独立完成状态 | 五个公共字段独立保留；业务放 payload_json，四个状态放 status_json。首次 created_at 起 14 天物理清理，包括软删明细；不重复保存 envelope 或 stored。 |
| processing_tasks | 四个消费者各自的租约、重试时间与错误 | 不复制完成状态；UNIQUE(event_row_id,consumer) 同时支持按事件清理，删除重复的 event_row_id 单列索引。完成即删除任务行。 |
| model_dimensions | provider + model 的统一身份、未知模型 | 事件、用量统计、费用统计共用一个整数外键；不在每条记录重复长模型名。未知模型 id=0。 |
| skill_dimensions | 私有技能稳定身份与可变展示名 | skill_key 是身份，public_name 是标签。改名不应改变历史调用身份。 |
| harness_metrics | 会话、轮次、消息、工具调用、代码、活动时长 | 删除与模型统计重复的 22 个 Token、请求与覆盖字段。保留工具级行为；无明确技能身份的调用也可计入工具级技能次数。 |
| model_metrics | Token、组成、覆盖、模型请求 | 同时支持模型和工具用量查询。工具总量直接按 harness 求和，必须包括 unknown 模型。 |
| skill_metrics | 按技能的调用、成功/失败、耗时 | 与模型维度没有必然关系；不制造 model × skill 的组合行。 |
| cost_metrics | 按模型归属和币种的有效金额及定价覆盖 | 删除 cost_scope 与重复工具总额行。每笔有效金额只归属一个模型或 unknown；工具金额按模型求和，币种分开。 |
| bucket_entity_state | 粒度内会话/轮次去重、消息标记及活动时长选择 | 同会话两天每天计 1，月计 1；会话时长要替换同日轮次兜底。仅有累计数和事件完成状态无法做到。删除通用 revision。 |

四张统计主题表都用 grain=hour/day/month。三种时间粒度共用表结构，但各有独立消费者和事件状态。按模型聚合的 Token 不再额外写入工具表；不能为方便一次 SELECT 就同步维护两套相同总数。

## 3. 字段和索引的取舍

- 删除所有 projection_generation、三个事件 generation 以及统计桶的 input_revision/applied_revision。每个桶只有一份已提交结果，处理完成以事件对应状态为准。
- 保留 schema_version（事件协议）和 metric_semantics_version（统计公式含义）。已有 schema_meta 管理库版本和定价配置，不新建通用版本配置表。
- fact_revision 默认 1。只有具体策略证实来源提供可更正事实，并能保证先后次序和撤回旧贡献时才启用修订。不能因内容 hash 或 mtime 变化就无条件生成新事件。
- 随身份表删除 source_content_hash、source_revision_json 等仅属于该表的字段；不转存到 extra 或 decoder_state。events 保留 content_hash，用于同 ID 内容冲突检测；保留期内重复读取复用已冻结的事件时间。
- 来源表保留四个辅助索引：来源业务唯一键、来源与 harness 复合外键所需唯一键、到期扫描、过期租约扫描。配置页的 enabled 列表不单建索引。租约扫描包括已停用但仍有在途任务的来源。
- 任务表只保留业务唯一索引与 due/lease 两个部分索引；不再给四个事件状态各建一套索引。
- 来源与 harness 的复合外键已保证来源存在，删除 events 上重复的来源单列外键。
- 统计唯一索引服务“grain + 时间范围”；仅工具和模型的已有筛选补索引。Skill 任意时间范围的 SUM 排名不能用单列 use_count 索引解决，因此不加。

每表前五列统一为 id、created_at、updated_at、delete_at、extra。创建/更新/软删时间是独立的 UTC 毫秒整数；delete_at 为 NULL 表示未删，extra 默认空 JSON 对象，只存本地可选扩展，不放必需业务字段、处理状态、账号或凭据，不默认上传。

全部本地 account_id 字段及其索引/复合外键已删除。账号只在同步认证上下文中出现，不建立认领或归属迁移；任务直接引用 events.id。上传从冻结的事件头和 payload_json 确定性构造，不复制完整 envelope；status_json 独立变化，不影响内容摘要。

业务唯一键覆盖软删行，删除不释放身份；到期领取和明细读取排除软删，租约回收与物理过期清理保留软删行。保留期内事件判重和历史维度引用仍能找到软删记录。没有为每表追加 delete_at/updated_at 索引，也没有添加自动更新时间或删除触发器。

## 4. 不为了假设的异常扩充通用模型

当前 ZCode 适配器目录包含 session summary 查询，而采集驱动优先读取已完成的逐次工具明细。会话累计快照与单次完成记录要分开处理，这不能证明所有已完成用量都会事后修改。参考 [策略查询](../collector/adapters/zcode/src/lib.rs:30)、[实际驱动](../collector/crates/acquisition/src/drivers.rs:528)。

首版优先使用有稳定 ID 的完成明细；累计用量由策略按已提交基线提取增量。无法证明可累加的快照不能每读一次就算一个新请求。遇到确有修订语义的来源，仅在原生顺序和旧贡献可用时处理，不给所有来源建一套永久版本管理系统。

SQLite 中“某个旧 rowid 之后才变为 completed”是读取覆盖问题，应该由该策略保存待复查边界来处理；增加 fact_versions 表并不能找回游标已经跳过的行。

## 5. 精简后的事务边界

1. 采集提交：校验来源租约和 commit_seq → 查保留期内 events → 新事实按选定时间做当天准入 → 写事件、任务 → 更新游标、解析基线和忽略计数 → 同事务提交。重复事实优先复用冻结身份，不重新计算 TTL。
2. 统计提交：校验事件对应状态、有效租约、未软删和未过期 → 在 writer 事务内读取最新实体状态、计算实际贡献 → 更新桶和实体状态 → 按 JSON 路径更新事件状态、维护 updated_at 并删除任务 → 同事务提交。不能把事务外按旧状态计算的整行覆盖回来。
3. 上传：事务内领取，事务外并发 HTTP；校验逐事件 ACK 的身份与内容摘要后，在匹配的事件和租约下提交状态；认证只保留在本次请求上下文。每 5 秒扫描到期任务和超时租约，失败的低序号事件仍能重新入队。
4. 清理：按首次 created_at + 14 天物理删除事件及任务，包括已软删明细，保留统计和来源游标；每个仍有未完成消费者的过期事件只给来源计数一次，不伪造 ACK。

需要修复统计时，只在完整已准入事实或可信基底覆盖受影响范围的前提下，暂停该消费者并事务替换相关桶、实体状态和事件状态；失败回滚。若修复范围太大或缺少旧贡献，必须先界定可恢复范围，不能清空全历史后只用剩余 14 天明细回填。当前不提供多版本热切换、原库历史从头重放或任意历史更正的保证；需要重新开始本地采集时走重装并初始化本地数据的流程。

14 天控制事件细节量，统计、来源游标和必要实体去重状态各有保留用途；不再额外保存永久逐事件身份摘要。服务端按 occurred_at 过滤事件时间范围，重放时刻不参与归属，范围内重复仍靠服务端事件唯一键处理。

## 6. 验证范围

生成脚本在内存 SQLite 执行全部 DDL，检查 10 张表均以 id 为主键、183 个字段均有注释、每表五个公共列一致、events 为 23 列且全库没有账号字段、外键与关键约束有效。索引脚本使用合成数据验证查询路径，并验证工具总量能从含 unknown 的模型行求和、费用不会因为同时存工具和模型范围而重复。

这些检查证明本地草案可执行、关键访问路径可用；时长替换、费用来源选择、并发 ACK 和首次初始化仍需业务实现中的场景测试，不能用建表成功代替。
