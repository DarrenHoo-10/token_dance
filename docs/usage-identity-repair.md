# 用量身份去重漏计修复

适用于旧服务端把费用事件误认为同一身份的 Token 事件副本，以及混合批次将缺失身份写成全零哈希导致的漏计。修复后，去重按账号、工具、事件类型、有效身份匹配；缺失身份写 NULL，汇总忽略历史全零身份。所有权依据事实链的首次入库确定，镜像副本不能抢占原事实的后续修订；同一事实的修订仍由正常修订逻辑处理。

## 发布与执行

先完成测试环境发布与回归，再将同一改动合入 main，从干净且 HEAD 等于 origin/main 的工作区构建生产服务与 `server/cmd/usage-identity-repair`。生产数据修复单独执行，不在启动或迁移中自动触发。

1. 记录构建分支、完整 SHA、目标数据库及执行时间。暂停目标环境 API、worker、灰度同步和相关数据清理，创建一致性数据库备份。修复工具使用该环境已有配置；不将 DSN、账号或事件正文写入日志、仓库或发布包。
2. 默认运行 `token-dance-usage-identity-repair`，只读预览。日志只包含扫描游标、事件数量、全零身份数量和预计重新入队的粒度数量。干跑不会写身份、状态或任务。
3. 审核数量后运行 `token-dance-usage-identity-repair --confirm`。每条事件使用独立事务，修正全零身份为 NULL；只有状态为 4、没有同类型更早所有者、没有更高修订的保留事件重新入队。已计入、在途、隔离、软删除和真正重复的事件不重排。失败后可从报告的最后成功游标通过 `--after-id` 继续；重新从零执行也不会重复累加。
4. 恢复修复后的 worker，等待 telemetry_tasks 与 dirty-day/outbox 队列处理完成，再核对 hour/day/month 的 Token、请求数、费用和个人/榜单/团队/社区视图。正常 worker 负责应用增量、标记脏日和刷新派生视图。最后恢复 API、灰度同步与清理。

`--batch-size` 默认 200（范围 1..1000），`--timeout` 默认 1h。游标仅为该次扫描定位，不是业务同步水位。不要同时运行多个修复进程。若有残留的同事件同粒度任务，工具会事务回滚并停止，不会覆盖租约。

## 边界

工具不清空汇总，不盲目重放全部事件，不调用全库 stats reset。仅恢复仍在 telemetry_events 中、尚未计入的最新事实；原始事件已被保留策略清理的历史，必须先从可信备份或设备恢复后另行审核，不能将现存部分事件当作完整历史重建。真正重复或旧修订的状态 4 会保留。

测试覆盖费用先到、同请求的 Token 与费用均计入、跨设备副本及修订不重复累加、缺失身份存 NULL、历史全零身份不参与去重、干跑无变更、针对旧漏计的补算和重复执行。
