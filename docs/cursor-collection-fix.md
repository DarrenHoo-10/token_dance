# Cursor 真实用量采集修复

## 根因

原管线只注册 transcript JSONL。这些文件确实被读到了 EOF，但实机记录仅含角色和消息内容，没有 token 字段，最终没有生成用量事件。旧采集器的能力状态同时被界面翻译为“需要配置”，掩盖了来源接入缺失。

Cursor IDE 数据库的 token 字段也可能为零；CLI 会话存储位于另一套 chats 目录。不能靠读取更多 transcript 或将 token 缺失值当零解决问题。

## 实现

- 新增 `official-usage-events` 来源，复用本机 Cursor 登录态，调用 Cursor 客户端自身定义的 `DashboardService/GetFilteredUsageEvents` 逐条明细接口。CLI 登录优先，存在但失效时不切换到 IDE 的其他账号。
- 只读 CLI 会话数据库中 hex JSON 元数据的 `agentId`、IDE `cursorDiskKV` 的 `composerData` 标识和 transcript 文件会话标识，形成当前机器的会话集合，缓存 30 秒。
- 只接收 `conversationId` 与本机标识精确匹配的明细。未归属本机的账号记录不落事件表；不会通过删除 cloud/subagent 前缀推断本机归属。
- 正式管线使用这一份 token 权威来源，不再将 transcript 当成第二份 token 来源重复入库。原始正文、CLI blobs、会话标题、账户标识和凭据都不进入事件表或上传数据。
- 北京时间当天固定起止窗口分页，每页最多 100 条；有后续页立即继续，无后续页或请求失败等待 30 秒，随后重新核对当天明细以覆盖延迟出现的记录。
- 分页游标使用现有来源事务，与事件、解码状态一同提交。空的本机匹配页仍推进；网络、鉴权或响应格式失败保持原检查点。
- 幂等标识由发生时间、会话标识、模型、四项 token 计数及相同明细的重复序号构成。重复序号跨页保存于当前毫秒分组，复扫不会将相同明细重复计数，也不会吞掉同毫秒的多条完全相同记录。金额变化不改变 token 事件身份。
- 输入上下文包含未缓存输入、缓存读取和缓存写入；总量为输入上下文加输出。保存精确 token、缓存读取、缓存写入和模型维度，不使用估计值补齐不存在的用量。
- 模型维度由单 writer 注册，公开模型标识参与 P0 内容哈希；编码后的上传事件哈希与落库时保持一致。
- 新管线向界面提供实际连接状态，覆盖旧适配器固定的能力降级状态；初始化、登录失效和读取失败显示具体状态，正常采集不再显示“需要配置”。

## 凭据与范围

请求仅发送到固定 Cursor 官方 HTTPS 地址，禁止跟随重定向，超时 12 秒，响应最多 2 MiB。凭据和身份摘要仅驻留内存；普通采集重启或登录态变化时重新核对当天窗口；全量重建重启恢复持久化分页游标，请求中途换账号则丢弃响应。

本次接入的是 token 明细，并未把账号额度百分比或账号全部明细转换为本机消耗；无法在本机找到会话证据的记录仍不计入。币种与账单修订不在本次接入范围内。

## 验证

- 桌面 Rust：243 项通过，9 项按外部条件忽略；其中本机只读验证已显式单独运行并通过。
- 前端用量逻辑：39 项通过；TypeScript 与 Vite 构建通过。
- 合成测试覆盖本机归属筛选、完整 token 分量、同毫秒重复明细跨页、重复采集、空匹配页、异常页顺序、零值与溢出、CLI/IDE 元数据识别、登录失效、中途换账号、事件到日统计、模型维度和上传内容哈希。
- 本机真实验证使用独立内存 SQLite：已验证归属本机的用量事件可以落库并完成日统计；私人用量数值仅保留在忽略的本地测试日志。未写入运行中客户端的数据库，未上传明细或会话内容。
