# 个人数据页统计修复

## 根因与调整

- 今天的趋势此前读取日统计，现在读取北京时间小时统计；多日查询仍使用日统计，筛选条件保持一致。
- Codex JSONL 中的 session_meta、task_started、task_complete 和用户消息此前被忽略。现在转换为会话/轮次活动事件；有配对起止时间才产生时长。完成后清除活动轮次上下文。
- 消息指标沿用现有轮次口径：开始和完成轮次合计，用户消息为用户触发轮次数，不等同于所有 assistant 流式消息条数。
- 服务端补记消息和时长覆盖计数；没有证据时返回不支持，避免显示成真实零。
- ZCode/OpenCode 仅从成功的 Edit/Write 生成代码统计，不再把普通 part 当作新增一行。Write 只报告可证实的生成行数，未知的覆盖删除量不填零。replace-all 缺少匹配数量时不计。
- Codex apply_patch 配对成功结果才计数；跨批次仅保存调用标识和数量，不保存代码正文或文件路径。
- 删除预估费用卡片，保留已有 API 字段兼容性。

## 幂等与历史边界

Token 事件身份不变。新增活动和 Codex 编辑事件使用稳定的原生会话、轮次、调用身份；文件重扫不会重复入库。
ZCode/OpenCode 代码事实保留 fact_key，用 revision 2 表达新解码内容，避免与旧占位内容产生冲突。现有通用代码统计对 revision 采用追加处理，因此旧 revision 1 的 added/removed 占位统计不会自动撤销；生成行数原来没有上报，不会因此重复。不得把这次修复描述为已完成历史 added/removed 清理。

旧版本没有落库的活动和代码证据，需要升级后的客户端执行全量重建。发布时按既有软件版本重建规则配置正式版本；本次不占用或复用发布版本号。客户端重建不等于服务端清库，Token 幂等身份必须保留。
