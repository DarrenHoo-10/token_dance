# 费用与会话时长修复

## 问题与口径

旧价格回填只处理旧用量库，事件流水线没有生成费用事件；费用卡因此没有可展示的数据。新流水线使用已有价格目录，按模型与输入、输出、缓存计价。未匹配价格的模型仍为空，不伪造零费用。金额是 API 标价估算，不是订阅实际账单。

会话总时长是同一工具、同一设备、同一会话的最早与最晚事件时间差。等待时间包含在内；没有新事件时不按墙钟增长。并行会话分别相加。跨小时、自然日、自然月按北京时间切分。只有一个时间点的会话为零时长，不虚构开始时间。

Grok 的归一化输入已经含缓存；通用解码再加缓存导致输入重复。修复后只计一次，以事实 revision 2 替换 revision 1，幂等事实身份保持稳定。

## 实现

- 费用事件使用用量事实的稳定作用域与修订号。报价版本由用量修订与价格目录时间组合（用量修订 × 10^10 + 目录 UTC 秒），同一报价版本的内容不变。目录刷新且金额变化时生成更高版本，替换旧报价，不叠加；本地清库重建后也不会以原报价身份上传不同金额。金额未变时不生成新事件。
- 本地 `estimated_price_table` 映射为协议 `calculated_price`；哈希与上传共用转换，避免本地约束与服务端枚举不一致。
- 会话范围独立于保留 14 天的事件明细。新增 `session_extents` / `telemetry_session_extents`，按设备（服务端）、工具、会话、粒度唯一；仅保存首尾时间，不保存会话正文。
- 数据库现有 `active_duration_ms` 字段承载新口径，页面改名为“会话总时长”。旧活动时长清零后只重放时长投影，不重复累计 Token、代码行和消息数。
- 本地补偿任务每批最多 128 条，补费用和已完成事件的会话范围。服务端聚合任务同样分批补时长。重启可重复扫描，范围和报价写入均幂等。价格目录按文件变化缓存，更新后从头检查未报价事件。
- 清理账户、删除设备数据和手动重建包含会话范围表。

## 已有数据与发布限制

时长自动补算覆盖仍保留的事件；已物理删除的明细无法凭空恢复首尾时间，需原始会话记录重建。Grok 已经读过的历史原始记录需重建重读，才能生成 revision 2；本次不修改已冻结的 revision 1。

当前测试 release 分支与本功能分支已经分叉，存在不同的 0014 迁移（本次新增会话迁移使用 0016，避开已占用的 0015）。部署前必须整合迁移历史，不能直接覆盖正在运行的测试服务，不能给已执行迁移改名或改内容。正式服务与桌面正式发布仍须从 main。

## 验证
